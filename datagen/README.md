# SCAMP-Trie Data Generation

This directory contains tools for generating IPv6 Forwarding Information Base (FIB) datasets used in the SCAMP-Trie evaluation. The datasets span **four network scenarios** across two categories:

| Category | Scenario | Data Source | Generator |
|----------|----------|-------------|-----------|
| **Synthetic** | ISP Edge | Real ISP ASN/prefix delegations | `scenarios.app` (C++) |
| **Synthetic** | Cloud Gateway | Azure-style /56→/64 allocation | `scenarios.app` (C++) |
| **Synthetic** | Host | Random /128 address assignment | `scenarios.app` (C++) |
| **Real-world** | IXP (Backbone) | RIPE NCC RRC BGP snapshots | See [IXP_DATA.md](IXP_DATA.md) |

## Quick Start (One-Click Generation)

To generate **all synthetic datasets** (ISP Edge, Cloud Gateway, Host) in one command:

```bash
cd datagen
./gen_all.sh
```

This generates:
- **13 base datasets** (~256K prefixes each): 7 ISP edge, 3 cloud gateway, 3 host
- **18 scaling datasets** (256K–1024K prefixes): 6 per scenario

To generate **base datasets only** (skip scaling variants):

```bash
./gen_all.sh -s
```

> **Note:** IXP (backbone) data is not generated by this script. It requires downloading real BGP snapshots from RIPE RIS. See [IXP_DATA.md](IXP_DATA.md) for step-by-step instructions. Pre-generated IXP FIBs are already included in [`../data/`](../data/).

## Requirements

- **Linux environment** (the generator compiles and runs on Linux; tested on Ubuntu)
- **g++ 7+** with C++14 support
- **GNU Make**
- **pthread** (standard on Linux)
- No external libraries beyond the C++ standard library and pthread

## Scenario Details

### 1. ISP Edge

Simulates IPv6 FIBs at ISP edge routers. Seven real-world ISPs from diverse regions are modeled using actual ASN-to-prefix delegation data:

| # | ISP | Abbreviation | Region |
|---|-----|-------------|--------|
| 1 | Kabel DE | kab | Germany |
| 2 | Orange | orag | France |
| 3 | DTAG | dtag | Germany |
| 4 | Sky UK | sky | England |
| 5 | Free SAS | free | France |
| 6 | Netcologne | netclg | Germany |
| 7 | Comcast | cmt | America |

**Generation method:** Loads the `data/pfx_asn.map` file containing real prefix-to-ASN mappings from [CAIDA](https://www.caida.org/). For each ISP, prefixes are generated at length-specific proportions (derived from real ISP subnet delegation patterns) by randomly assigning sub-prefixes under the ISP's owned prefix space. Generated prefixes span prefix lengths from /47 to /64.

**Base output:** `isp1_kab.fib` through `isp7_cmt.fib` (256K prefixes each)

### 2. Cloud Gateway

Simulates IPv6 FIBs at cloud provider gateway routers using the **Azure-style allocation strategy**:

1. Allocate a `/56` prefix to each tenant (Virtual Private Cloud / VPC)
2. Derive `/64` subnets under each `/56`
3. Apply an **80/20 distribution**: 80% of tenants get exactly 1 subnet, 20% get 2–256 subnets
4. Guarantee all allocated prefixes are unique

This strategy is representative of major cloud providers (AWS, Azure, Alibaba Cloud) that allocate `/56` blocks first and then derive `/64` subnets.

**Base output:** `AWS_256k_v6.fib`, `Azure_256k_v6.fib`, `Google_256k_v6.fib` (256K prefixes each)

### 3. Host

Simulates IPv6 FIBs on host machines, where all entries are `/128` host addresses. Addresses are randomly generated under the `0x64::` prefix with a configurable randomization parameter that controls how many bits are randomized (64, 72, or 80 bits below the prefix).

**Base output:** `host-rd64.fib`, `host-rd72.fib`, `host-rd80.fib` (256K prefixes each, with 64, 72, and 80 bits of randomization respectively)

### 4. IXP (Backbone)

Real-world IPv6 BGP routing snapshots from 23 [RIPE RIS](https://ris.ripe.net/) Route Collectors (RRCs) deployed at major Internet Exchange Points worldwide. This is the **only scenario that cannot be generated synthetically** — it requires downloading RIPE RIS BGP raw data and parsing it with external tools.

See **[IXP_DATA.md](IXP_DATA.md)** for the complete step-by-step guide. Pre-generated IXP FIB files are already available in [`../data/`](../data/).

## Advanced Usage

### Custom Prefix Count

The `scenarios.app` binary supports arbitrary prefix counts via the `-N` flag:

```bash
cd scenarios
make data
./build/scenarios.app -O 2 -N 512000          # ISP edge, 512K prefixes
./build/scenarios.app -O 4 -N 128000 -o out   # Cloud gateway, 128K prefixes
./build/scenarios.app -O 5 -N 100000 -P 64 -o out  # Host, 100K prefixes, param=64
```

### Command-Line Options

```
scenarios.app -[M:O:N:o:P:h]

  -M <str>   Mode by name: backbone | isp-edge | campus | cloud-gateway | host | others
  -O <num>   Mode by number (see below)
  -N <num>   Total number / scale (default: 256000)
  -o <path>  Output path without .fib extension
  -P <num>   Host randomization param (e.g., 64, 72, 80; default: 72)
  -h         Print help

Mode numbers:
  1  backbone    (not implemented — IXP data uses real BGP snapshots)
  2  isp-edge    ISP edge router FIB
  3  campus      (not implemented)
  4  cloud-gateway  Cloud gateway FIB
  5  host        Host machine FIB
  6  others      (not implemented)
```

### Regenerating Individual Scenarios

The standalone scripts `gen_cloud2.sh` and `gen_isp2_host2.sh` can be used to regenerate scaling datasets for specific scenarios without re-running the full pipeline.

## Output Format

All generated `.fib` files follow the same format — one prefix per line:

```
<IPv6_High64>.<IPv6_Low64>/<PrefixLength>
```

Example:
```
2610000000000000.8923456789ABCDEF/64
```

This format is compatible with all algorithms in the SCAMP-Trie evaluation framework (see [`../eval_readme.md`](../eval_readme.md)).

## Troubleshooting

### Build fails with "unrecognized command line option"
Ensure g++ 7 or later is installed:
```bash
g++ --version
```

### "binary not found" after build
The makefile may silently fail if the build directory is not writable. Check permissions:
```bash
ls -la scenarios/build/
```

### ISP generation fails with "pfx_asn.map not found"
The `pfx_asn.map` file must be at `datagen/data/pfx_asn.map` relative to the repository root. The `gen_all.sh` script handles paths automatically; if running `scenarios.app` manually, ensure you run it from the `scenarios/` directory:
```bash
cd datagen/scenarios
./build/scenarios.app -O 2 -N 256000
```

### File already exists errors
The `gen_all.sh` script overwrites existing files by default. To preserve existing data, back it up first:
```bash
mkdir -p ../data/backup
cp ../data/*.fib ../data/backup/
```
